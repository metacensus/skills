## Choose the layer by what a failure would mean

A test belongs at the lowest layer that can fail for the reason it names, as in [`dev-testing-go`](../dev-testing-go/SKILL.md#choose-the-layer-by-what-a-failure-would-mean).

| Layer | Runs | Catches what the layer below cannot |
|---|---|---|
| Logic | Vitest on pure functions beside their code; a state machine driven from a table of inputs into one golden JSON fixture, regenerated by a flag and reviewed as a diff | a wrong result or transition |
| DOM | Testing Library in a DOM environment, queried by role and label, input through `user-event` | markup, labels, and state on input — each form state: busy, an error keeping the typed values, success |
| Browser | Playwright, per route | layout, hydration, focus, CSP, keyboard, computed colour |
| Artifact | the image that ships | what the server answers: status, headers, paths |

A render to a string is not a DOM test: nothing clicks it.

## Every route in a real browser

- **axe (`@axe-core/playwright`) runs on every route, in light and dark**, and fails on any WCAG 2.2 A or AA violation, impact ignored: the tags already drop best-practice rules, and a moderate failure is still a failure of the standard. axe tags each rule by the WCAG version that introduced it, so the list names every one: `withTags(['wcag2a', 'wcag2aa', 'wcag21a', 'wcag21aa', 'wcag22aa'])`.
- **Routes are globbed, never listed**: the route files for an app, every built `*.html` for a static site. The spec fails when the glob finds none, so a moved output cannot pass as empty.
- **axe runs again with each form state shown and each dialog, menu and disclosure open**, since a closed one is not in the tree.
- **axe over built HTML in jsdom is not this check**: nothing is laid out, so contrast, hydrated islands and keyboard go unseen.
- **A console error or CSP violation fails the page.**
- **A gap is an issue**, fixed in the change or excused for that rule alone: the route's test calls `.disableRules([id])`, and a separate `test.fail()` naming the issue checks only that rule. It turns red once the gap closes, so no entry outlives its bug as an allow-list entry would; the rest of the route still gates.

## Keyboard paths are tests

Each interactive flow runs by keyboard alone, its assertions reading the focused element by role:

- Tab reaches every control, in order, with focus visible;
- Escape closes a dialog and returns focus to its trigger;
- Enter submits a form.

## Probe the image as built

The suite runs the image `SERVICE_IMAGE` names, as [`dev-ci-github`](../dev-ci-github/SKILL.md#test-the-artifact-ci-built) builds it; a Go host's artifact suite carries the same probes. Each probe proves a [`dev-ui`](../dev-ui/SKILL.md) rule:

| Probe | Expects | Proves |
|---|---|---|
| `${BASE}/` | 200, `no-cache` | [one base path](../dev-ui/SKILL.md#one-base-path), [caching](../dev-ui/SKILL.md#caching-and-headers) |
| A deep link | the page, or for a single-page app the shell, `no-cache` | [caching](../dev-ui/SKILL.md#caching-and-headers) |
| A hashed asset, its name read from the base page so a rebuild cannot stale it | `immutable` | [caching](../dev-ui/SKILL.md#caching-and-headers) |
| A missing hashed asset | 404, not HTML | [caching](../dev-ui/SKILL.md#caching-and-headers) |
| A static site's unknown path | 404, its own page | [caching](../dev-ui/SKILL.md#caching-and-headers) |
| Any page | the security headers | [headers](../dev-ui/SKILL.md#caching-and-headers) |
| `robots.txt` per `Host` | production allows, any other host disallows | [headers](../dev-ui/SKILL.md#caching-and-headers) |
| The healthcheck | healthy | [one base path](../dev-ui/SKILL.md#one-base-path) |

## A package renders without a browser

The built package is imported through its published entry point in Node, with `window`, `document`, `localStorage` and `matchMedia` defined as throwing getters, and each export rendered to a string. A throw names the component that touched a browser global at render. Built, not source, because the bundler's output is what a static render runs.

## Contrast is computed from the tokens

The test reads the token source, resolves each `light-dark()` to its two values, and checks a table of role pairs declared once in the test, the [rule](../dev-ui/SKILL.md#tokens-from-one-source) `dev-ui` states:

- text on its ground at 4.5:1 or more;
- large text, borders, the focus ring and chart series at 3:1 or more.

A role in no pair fails, so a new role is paired when added. axe in the browser is not enough: it sees only the roles a visited route renders.

## One harness

- **A shared Playwright preset from a package** holds the light and dark projects, the axe helper, the route glob, the console and CSP listener, and blocks every origin but the served one, so no test depends on a third party.
- **A suite is the preset and its specs**: no runner on `playwright-core` with axe injected by hand.
- **Browser tests run against the built output, never the dev server**, since the build is what ships.
- **Every suite runs in CI as a `make` target** ([`dev-ci-github`](../dev-ci-github/SKILL.md#ci-runs-make)): `test` for logic and DOM, `test-browser`, `test-artifact`.
- **Browsers come from Playwright's install**, never a path on one machine.
