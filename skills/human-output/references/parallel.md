# Parallel documents

A page a person reads beside the document an agent reads, its source. It holds the source's knowledge in the source's order, drawn for the eye; it adds no fact the source does not hold.

## The first screen

A one-line thesis as a blockquote; for a document that fires on a trigger, a line saying when; then, where the source has a main structure or flow, one map of it drawn whole in its family's form.

```
> A pull request's review runs from request to verdict.

Fires: a review requested, or asked whether a PR may merge.

Request → Read → Run → Findings → Verdict
```

## Headings

Each `##` heading copies the source's, word for word and in order; a section with nothing to carry keeps its heading over one line.

## Sections

- A table the source holds usually stays a table, one attribute per column and one value per cell; a column that never varies can go, and tables that share a key can merge.
- Facts the source scatters often form a view it never draws, a matrix or a path grid; drawing that view adds no fact, and is often the page's biggest gain.
- Number what a reader cites: stages, questions, options. Lists of facts usually read better bulleted.
- A link goes to its target's parallel page.

## Length

At most a third of the source's prose words, the words outside tables and code; a table is held to trimmed cells instead.
