Nothing is ever elegant, only nearer, so "fine as is" is never a finding.

## The test

Every element must name what the reader would lose without it. Being true, or already written, is not enough.

## The scope of an alteration

Work at the largest element first — cut or merge a section before polishing sentences — and read an urge to add as a sign that nothing has been found to remove yet.

## Prose about code

Non-code text is allowed only as a summary one level above its subject, or as an illustration shorter than the code it explains. Code documents itself nearly always, so a comment usually means delete it or refactor, and any refactor that keeps package- and feature-level behavior unchanged is in scope.

## Moves

A ranked list of edits, and the ranking is the point: retire (including a pointer, unless no better lead lets most who need its target find it), merge, move up, replace with structure (a name, type, or check), derive what is computable, rewrite whole, mark open questions as holes, and only last add — saying what the addition replaces and what was left alone.

## The model

An element's scope (how fast reality exposes it as wrong) and time (plan, current fact, or record) name a cell with its own rules. Confidence is the check an element passed; agent output starts at bare assertion.

## Before you finish

Run `check-cells.mts --diff` to see which cells were touched, hand the diff to the `elegance-review` agent without explaining it, and grep for whatever points at what changed.

## The review loop

The owner of a change runs its reviewer for at most three rounds, whatever the standard. Both name the spans they keep returning to, which tells improvement that converges (it lands) from disagreement, stated or not (that span goes up with both positions).
