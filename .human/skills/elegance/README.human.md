## Changing the skill

The skill is held to its own test. An edit names its cell and what it retires. Theory's section numbers are link anchors, so a move fixes its links first. Each table lives in one file, and `check-cells.mts` fails if a cell and the grid disagree. The author never reviews their own change — `elegance-review` does. Step-by-step rules belong in cell files.

## The gradient

Each file runs from abstract principle down to concrete action. The action-level questions deliberately repeat the abstract rules as prompts to act, because that is what overcomes the model's inertia; reviewers are told not to cut them as duplicates. How far down a file spells things out reflects how little the model is trusted to derive alone.

## Instruments

Only `check-cells.mts` is a hard gate. A review reporting neither findings nor attempts counts as failed.

## Holes

Nothing measures whether a pass shrank anything, nothing forces the review, the trigger cannot tell a tier-5-only change because a commit message is never a changed path, the final round's fixes land unreviewed, portability is untested, and how to bound a pass when everything is poor is open.
