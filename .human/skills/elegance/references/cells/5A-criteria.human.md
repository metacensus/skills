> A criteria item says what the file should contain and when it is done, in a few observable, binary lines.

```
          4A plan
              ↓
5A criteria ↔ 5B code ↔ 5C commit
```

Tier 5 · scope File · time Future

## Example

What the file should contain · the acceptance criteria that say when it is done.

## Location

**Git/Issues**, in the location key (grid).

## Clear when

a few observable, binary criteria · a verification command · bounded scope · no blocker open · whoever accepted them is named

## Excess

| Excess | Test or move |
|---|---|
| **A criterion that describes the implementation** | Does it name what is observed, or how it is built? Rewrite how into the observation; how is the diff's. |
| **Background restating the parent** | Link the parent. |
| **Ambiguity words** (*robust*, *clean*, *appropriate*) | They lengthen a criterion and make it less binary; rewrite as a binary question. |
| **More than a handful of criteria** | Count them. Past a handful it is a plan wearing an item's clothes; split it. |

## Cost

Hours to days · vague criteria are built as slack rather than absorbed.

## Moves

1. Ambiguity → rewrite as binary questions; a criterion that can be a test → write it as the test
2. Item ends → retire as done · done differently · dropped, naming which
