> A plan decomposes a parent into children that can each be worked alone, with its non-goals stated.

```
            3A design
                ↓
4A plan ↔ 4B surface ↔ 4C merges
                ↓
          5A criteria
```

Tier 4 · scope Module · time Future

## Example

A parent item with its children and its non-goals.

## Location

**Git/Issues**, in the location key (grid).

## Clear when

children = the decomposition · each workable without reaching up · each with binary criteria → non-goals present · confidence = standing of the agreement to the plan

## Excess

| Excess | Test or move |
|---|---|
| **A parent that restates its children** | Cover the parent and read the children; what stays true only in the parent is what it holds, the rest was a copy. Children are linked. |
| **Design in the plan** | The target lives in [3A](3A-design.human.md); the plan links to it and sequences the work. |
| **Non-goals padded into a rationale** | One line: what is out, at most why. State restraint; do not argue it. |
| **A child with a paragraph of context** | Try working the child without reaching up; if you cannot, fix the parent, do not copy it down. |

## Cost

Weeks · scope creeps across children, and slack is built rather than absorbed.

## Moves

1. Child reaches up → rewrite the parent
2. Split children → add the missing criterion or non-goal as one line
3. Close as done · not done · deviated (theory §4.3) → this alteration writes [4C](4C-merges.human.md)
